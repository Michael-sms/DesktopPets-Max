# M3 完整动作集审阅指引

## 本轮完成范围

- Idle：12 帧、2.4 秒呼吸循环。
- Hover：12 帧、1.2 秒抬手回应循环。
- Loading：16 帧、1.6 秒观察等待光球循环。
- Working：12 帧、1.2 秒操作悬浮终端循环。
- 五段 6 帧、0.36 秒非循环过渡：
  - `idle_to_hover`
  - `hover_to_idle`
  - `idle_to_loading`
  - `loading_to_working`
  - `working_to_idle`
- 播放器支持优先播放过渡、过渡完成后进入目标循环，以及忙碌状态对当前过渡的替换。
- M3 样例角色成为默认桌宠资源。

## 推荐审阅方式

自动轮播完整状态链：

```powershell
.venv\Scripts\python.exe main.py --demo
```

轮播顺序为：

```text
Idle → Hover → Idle → Loading → Working → Idle
```

这样可以依次看到五段标准过渡。也可以正常启动后使用数字键：

- `1`：Idle
- `2`：Hover
- `3`：Loading
- `4`：Working

## 动作语义

- Hover 使用抬手、开心表情，强调“发现用户”。
- Loading 双手观察薄荷蓝光球，强调“等待反馈”。
- Working 双手主动操作悬浮终端，强调“正在执行”。
- 三种状态使用不同手势、表情和道具，不只依靠状态标签区分。

## 动画一致性策略

每个状态只使用一张经 M2 角色锚点约束的动作锚点，再通过本地确定性缩放、轻摆和位移扩展连续帧。这样能够保持脸部、发型、服装和道具在循环内完全稳定。状态间使用短暂的淡出压缩/淡入恢复过渡，避免 AI 独立补帧产生的双影和身份漂移。

## 自检标准

- 9 段动画、共 82 帧全部能由 manifest 加载。
- 全部帧为 512 × 512，具有透明通道。
- 四个主循环落脚点波动不超过 2 px。
- 五段过渡均为非循环，播放完成后进入正确目标状态。
- 新的忙碌状态可以替换尚未结束的低优先级过渡。
- M1 状态机、M2 创建流程与原资源校验测试保持通过。

## 建议重点反馈

- Hover 是否足够亲切但不过度抢占注意力。
- Loading 的等待感与 Working 的主动操作感是否明显区分。
- 各状态的动作幅度和循环速度是否自然。
- 0.36 秒淡出压缩过渡是否合适。
- 状态标签是否继续保留，或在下一阶段改为仅调试模式显示。
